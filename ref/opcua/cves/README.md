## Key Vulnerability Patterns for Fuzzing

1. **Message Size Field**: 4-byte size in header - values exceeding MaxMessageSize, zero, or smaller than header
2. **NodeId Encoding Byte**: Invalid encoding byte values trigger unhandled code paths
3. **Variant Array Dimensions**: Multi-dimensional arrays where dimension product overflows or doesn't match data
4. **String/ByteString Length Prefixes**: 4-byte length prefix with -1 (null) vs 0 (empty) vs MAX_INT
5. **ExtensionObject TypeId Resolution**: Unknown TypeIds with non-null body requiring blind skip by length
6. **Chunk Reassembly**: Sequence number gaps, abort chunks mid-stream, final chunk without prior continues
7. **Security Header Sizes**: Asymmetric security header with oversized certificate/thumbprint fields
8. **Nested Structures**: Deeply nested data types (Variant containing Struct containing Variant) causing stack exhaustion
9. **Hello/Acknowledge Parameters**: Buffer sizes, max message sizes, max chunk count with extreme values
10. **StatusCode Array**: Diagnostic info structures with recursive InnerStatusCode chains

## Exploits and PoCs

### CVE-2022-29862
- **Product**: OPC Foundation UA .NET Standard Stack v1.04.368
- **Type**: Infinite Loop / DoS
- **CVSS**: 7.5 (v3.1)
- **Server-side**: Yes -- server enters infinite loop from crafted OPC UA message, causing application hang
- **Root cause**: Parsing logic for specific message structures enters an infinite loop when encountering malformed data patterns (likely in Variant or ExtensionObject decoding)
- **PoC**: No public PoC (Claroty opcua-exploit-framework may contain corpus samples that reproduce this)
- **Metasploit**: N/A
- **Advisory**: [NVD](https://nvd.nist.gov/vuln/detail/CVE-2022-29862)
- **Analysis**: The official OPC Foundation .NET Standard Stack is the most widely used OPC UA implementation. An infinite loop triggered by a single crafted message is a classic fuzzing find -- a coverage-guided fuzzer tracking execution count would flag this immediately.

### CVE-2022-29863
- **Product**: OPC Foundation UA .NET Standard Stack v1.04.368
- **Type**: Uncontrolled Resource Consumption / DoS
- **CVSS**: 7.5 (v3.1)
- **Server-side**: Yes -- crafted message triggers excessive memory allocation causing OOM crash
- **Root cause**: Message parsing allocates memory based on attacker-controlled size fields without enforcing maximum limits
- **PoC**: No public PoC
- **Metasploit**: N/A
- **Advisory**: [NVD](https://nvd.nist.gov/vuln/detail/CVE-2022-29863)
- **Analysis**: Classic length-field-controlled allocation. A fuzzer mutating string/array length prefixes (4-byte values) to MAX_INT or near-MAX_INT would trigger this.

### CVE-2021-27432
- **Product**: OPC Foundation UA .NET Standard Stack
- **Type**: Uncontrolled Recursion / Stack Overflow / DoS
- **CVSS**: 7.5 (v3.1)
- **Server-side**: Yes -- attacker triggers stack overflow via deeply recursive message structures
- **Root cause**: Recursive parsing of nested data types (Variant containing Variant, or ExtensionObject containing ExtensionObject) without depth limits causes stack exhaustion
- **PoC**: No public PoC
- **Metasploit**: N/A
- **Advisory**: [CISA Advisory ICSA-21-098-01](https://www.cisa.gov/news-events/ics-advisories/icsa-21-098-01)
- **Analysis**: OPC UA's type system allows arbitrary nesting (Variant->Struct->Variant->...). Without a recursion depth limit, a fuzzer generating deeply nested types crashes the server. This is a fundamental OPC UA attack pattern.

### CVE-2020-36429
- **Product**: open62541
- **Type**: Out-of-bounds Write / DoS
- **CVSS**: 5.5 (v3.1)
- **Server-side**: Yes -- OOB write in Variant_encodeJson for large recursion depth
- **Root cause**: JSON encoding of deeply nested Variant structures writes beyond buffer boundaries
- **PoC**: No public PoC
- **Metasploit**: N/A
- **Advisory**: [NVD](https://nvd.nist.gov/vuln/detail/CVE-2020-36429)
- **Analysis**: Affects the open62541 reference C implementation. JSON encoding path is triggered when the server exposes JSON-based APIs. A fuzzer generating deeply nested OPC UA Variants and requesting JSON encoding triggers the OOB write.

### CVE-2022-25761
- **Product**: open62541
- **Type**: Resource Exhaustion / DoS
- **CVSS**: 7.5 (v3.1)
- **Server-side**: Yes -- no limit on received chunks per session allows memory exhaustion
- **Root cause**: The server does not enforce MaxChunkCount or similar limits on the number of message chunks received per session, allowing an attacker to send unlimited partial chunks
- **PoC**: No public PoC
- **Metasploit**: N/A
- **Advisory**: [NVD](https://nvd.nist.gov/vuln/detail/CVE-2022-25761)
- **Analysis**: Stateful fuzzing that opens a session and sends many 'C' (Continue) chunk messages without ever sending 'F' (Final) would reproduce this. Demonstrates the importance of stateful protocol fuzzing for OPC UA.

### CVE-2022-39823
- **Product**: Softing OPC UA C++ SDK
- **Type**: Use-After-Free / DoS
- **CVSS**: 7.5 (v3.1)
- **Server-side**: Yes -- UAF when browse continuation points are exceeded
- **Root cause**: When the maximum number of browse continuation points is exceeded, the server frees memory that is still referenced, leading to use-after-free
- **PoC**: No public PoC
- **Metasploit**: N/A
- **Advisory**: [Softing Advisory](https://industrial.softing.com/fileadmin/psirt/downloads/syt-2022-8.html)
- **Analysis**: Requires stateful fuzzing that creates many browse sessions with continuation points. A fuzzer that tracks state and issues large numbers of Browse/BrowseNext calls would find this.

### CVE-2018-12585
- **Product**: OPC Foundation UA Java and .NET Legacy Stack
- **Type**: XXE / DoS + Information Disclosure
- **CVSS**: 8.2 (v3.1)
- **Server-side**: Yes -- XXE in XML-encoded OPC UA messages allows DoS and info leak
- **Root cause**: XML parser used for OPC UA XML encoding does not disable external entity resolution, allowing XXE attacks
- **PoC**: No public PoC
- **Metasploit**: N/A
- **Advisory**: [NVD](https://nvd.nist.gov/vuln/detail/CVE-2018-12585)
- **Analysis**: Targets the XML/SOAP encoding mode of OPC UA. A fuzzer injecting XXE payloads into XML-encoded OPC UA service requests would find this. Most OPC UA deployments use binary encoding, but XML mode is still supported.
